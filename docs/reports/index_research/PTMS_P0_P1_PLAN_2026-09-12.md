## 1. The "no market data" boundary — proposed rule, for ratification

P0–P5 must not read market data. That phrase needs one line of precision, because P1
(store-map correction) is impossible under the widest reading and the operator has already
accepted a result (C1) produced by exactly the kind of access in question.

> **Proposed rule.** Reading **schema, row counts, distinct-symbol counts, min/max dates,
> and file presence** computes no signal and no label, and therefore spends no research
> budget — this is `meta`-level access in the register's vocabulary. Reading **OHLC values
> into a feature, a signal, a label, a fitted parameter, or a trading rule** spends budget
> and requires an authorized window.

**Worked example (the C1 scan).** `count(distinct symbol)` per 1m file across 2022-12 →
2023-09 established that breadth begins 2023-01-02. No price value entered any
computation; no date acquired a label. Under the rule this is `meta` and spends nothing.
It is also the *only* way to catch a coverage claim that is wrong in both the charter and
the store map.

**Request:** ratify or amend this rule now, so it is settled once rather than re-litigated
at every phase.

## 2. P0 — Budget adjudication

**Objective.** A durable exposure register that future projects cannot dispute.

**Delivered with this plan (v1, seeded):** `governance/exposure/RESEARCH_EXPOSURE_REGISTER.md`
— level taxonomy, window-scoping rule, lineage-local vs global rule, enumeration method
with its proven failure mode, 10 index-1m rows, 6 breadth-1m rows, 15 other-surface
lineage rows, an unread-surface table, and a declared gap list.

**Two findings already surfaced by building it:**

1. **The enumeration method matters more than the enumeration.** Path-literal grep
   (`"candles/1m"`) returns **9** readers of the 1m store; component-wise grep returns
   **63**. The naive method misses `scripts/build_intraday_features.py` — the largest single
   exposure on the index surface — because the path is assembled from parts. A register
   built the naive way would have silently omitted its own biggest entry. Method is
   therefore recorded *in* the register, with the failure as evidence.
2. **Finding I-β — an active lineage carries an incomplete disclosure.**
   `INTRADAY_ANALOG_PATH_PROTOCOL.md` (2026-09-09; TRAIN and HOLDOUT run, SEALED pending)
   discloses A, the pair-ratio analysis, and DayType as prior reads of its SEALED window.
   It does **not** disclose `scripts/msrp/build_forward_vol_artifact.py`, which froze OLS
   coefficients on `NSE_INDEX|Nifty 50` 1m *and* 1d closes over **2023-01-02 →
   2025-12-31** — wholly inside that SEALED window.
   The protocol's claim is level-qualified ("never read **at construct level**") and MSRP's
   target is forward *volatility*, not direction, so the claim is not plainly false. It is
   escalated, **not adjudicated here.** This blocks nothing except the analog-path SEALED
   read — and it is exactly the class of dispute the register exists to prevent.

**P0 remaining work (register §7).** G-A/G-B/G-C: component-wise reader enumeration for
equity EOD, futures EOD, both options stores, and the 1d index store. G-D: window
determination for five intraday readers classified by name but not inspected. G-E: the
artifact-side closure check run systematically — every artifact under `data/` and
`docs/reports/` must map to a recorded reader, or the enumeration is incomplete.
G-F: operator adjudication of I-β.

**Acceptance criteria.**
- Every canonical store has a component-wise enumeration, not a path-literal one.
- The artifact-side check closes with zero unmapped research artifacts, or each exception
  is named.
- Method limits are stated in the register (deleted code, untracked probes, ad-hoc reads).
- Every row carries surface, window, level, family, consumer, and evidence.

**Effort:** G-A..G-E are mechanical, ~1 working session. G-F is an operator decision.

## 3. P1 — Store-map correction

**Objective.** `docs/DATA_STORE_MAP.md` must match the store.

**Known defect.** §9 asserts "2 syms pre-2024-10-17, 195–231 after" for the 1m store. Both
halves are wrong: the step is at **2023-01-02** (2 → 190), and the post-step count runs
**190 → 198**, never 231. The charter inherited this error.

**Method.** Re-verify every coverage claim in §9 by the same `meta`-level technique that
found C1 — do not re-assert any number the map already states. Specifically: 1m and 1d
symbol counts and boundaries; the 149-index claim on the 1d store; equity/futures/options
row counts and date ranges; the BSE file counts; the `deliv_*` fill rate; the "35 missing
1m files" and "2018: 223 vs ~246" claims.

**Complication to handle, not paper over.** `docs/DATA_STORE_MAP.md` is currently
**untracked on both `main` and this branch**. Correcting an untracked file leaves no
diff history. Recommended: commit it to this branch as-is first (preserving the erroneous
text as the baseline), then commit the correction as a separate diff — so the repair is
visible rather than retroactive. This follows the standing lesson that a substrate
certification certifies *provenance*, and provenance cannot be reconstructed after the fact.

**Acceptance criteria.** Every §9 claim either re-verified or corrected; the verification
command recorded next to the claim; no claim left asserted-but-unchecked.

manufactured to buy power. Its RFA will therefore hinge on `n_available` for the index

comes first.

construct named, until P0 and P1 close and P3 pins the catalogue.
